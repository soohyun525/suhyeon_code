## 1. 문제 정의

수확철 제주에는 **같은 시기에 비어 있는 것 네 가지**가 있다.

| 누구 | 비어 있는 것 | 근거 |
|---|---|---|
| 농가 | 일손 | "일당 10만 원에도 귤 딸 사람이 없다"(2026-11 보도). 하반기 농번기 4만 6천 명 투입 계획, 그중 1만 3천 명이 외국인 계절근로자 |
| 농어촌민박 | 겨울 객실 | 숙박 초과공급 약 4.7만 실, 농어촌민박 폐업률 평균 8.2%. 감귤 수확철(10월~2월)은 관광 비수기 |
| 전세버스 | 운행 일정 | 업계가 "운행할수록 적자"라며 경영난 호소(2026-03 보도). 수요가 수학여행·단체관광 철에 몰린다 |
| 청년 | 제주에 살아볼 기회 | 살아보기는 돈이 들고, 감귤 알바는 숙소가 열악한 단기 노동으로 끝난다는 후기 다수 |

넷은 서로의 해답인데 묶어 주는 주체가 없다. 농가 한 곳의 "3명, 5일"로는 민박도 버스도 움직이지 않는다. **여러 농가의 일정을 모아 민박과 버스 회사가 응할 만한 규모로 만드는 일**이 빠져 있다.

## 2. 서비스 한 줄 정의

**농가가 일손이 필요한 일정을 올리면, Agent가 주변 농가의 일정과 묶어 "숙소 + 셔틀 + 일" 패키지를 설계하고, 민박과 버스 회사에 각자의 이익이 숫자로 보이는 제안서를 만들어 참여를 끌어낸다. 완성된 패키지는 청년에게 "제주 시즌"으로 열린다.**

### 참여자와 각자가 얻는 것

| 참여자 | 내는 것 | 얻는 것 |
|---|---|---|
| 농가 | 필요한 인원과 날짜 | 숙소·이동이 해결된 일손 |
| 민박 | 비수기 객실 | 몇 주짜리 확정 투숙 |
| 전세버스 회사 | 비수기 차량 | 매일 정해진 통근 운행 |
| 청년 | 몇 주의 노동 | 숙소·이동·사람·기록이 갖춰진 제주 워킹홀리데이 |
| 농협·제주농업인력지원센터 | 구인 확인, 근로 조건, 계약 | 모집하기 쉬운 상품 |

Agent는 일자리를 직접 소개하거나 계약하지 않는다. 농가 일정의 확인과 알선은 농협·센터가 맡고, 제안서 발송도 사람이 확인한 뒤에 한다.

## 3. 메인 기능 — 시즌 패키지 만들기

### 3.1 흐름

```
1 일정 접수    농가가 위치, 필요 인원, 날짜, 작업 종류를 입력
2 묶기         가까운 농가·겹치는 날짜를 모아 "시즌" 단위로 묶음
               예) 남원 일대 11개 농가, 3주, 하루 평균 18명
3 거점 찾기    묶음 근처에서 민박이 모여 있고 저녁에 가게가 열리는 마을 선정
4 노선 짜기    거점 숙소 → 농가 승하차 순서와 시간, 노선버스로 되는 구간 제외
5 수지 계산    참여자별 손익: 민박 예상 수입, 버스 운행 수입, 청년 실수령액, 농가 부담
6 제안서 생성  민박용, 버스 회사용, 농협·센터용 제안서 각 1부
7 패키지 공개  조건이 맞춰지면 청년에게 보이는 "시즌" 페이지 생성
```

### 3.2 제안서가 매력적이려면

제안서는 상대의 숫자로 쓴다.

- **민박에게**: "귀 업소가 있는 읍면동의 숙박 업종 카드 매출은 1월이 8월의 ○○% 수준입니다. 이 시즌에 참여하면 12월 2일부터 3주간 6실이 확정됩니다. 예상 수입 ○○만 원."
- **버스 회사에게**: "평일 21일간 오전 6시 40분 출발, 오후 5시 30분 복귀, 하루 왕복 ○○km. 주말 2회 추가 운행. 비수기 유휴 차량 1대로 가능합니다."
- **농협·센터에게**: "이 권역 11개 농가의 3주 일손 수요가 숙소·이동과 함께 한 상품으로 정리되었습니다. 모집 공고 초안을 첨부합니다."

민박과 버스의 비수기 정도를 보여 주는 숫자가 센터의 카드 데이터에서 나온다. 데이터가 설득의 재료가 된다.

### 3.3 Agent가 스스로 판단하는 것

- **묶을지 말지**: 농가가 너무 흩어져 있거나 인원이 적으면 패키지가 성립하지 않는다. Agent는 "이 일정은 인원이 ○명 더 모이거나 날짜를 이틀 옮기면 성립한다"고 농가에 되돌려 준다.
- **수지가 맞는지**: 청년 실수령액(일당에서 숙박·교통 부담을 뺀 금액)이 기준 아래면 패키지를 공개하지 않고, 누가 얼마를 분담하면 맞는지 대안을 낸다.
- **어느 숫자로 설득할지**: 상대에 따라 제안서에 넣을 근거 데이터를 고른다.

## 4. 청년 쪽 기능 — 패키지를 "알바 이상"으로 만드는 것

메인 기능이 만든 패키지에 붙어서 청년이 참여할 이유가 된다. 상세 설계는 2차 안에서 가져왔다.

| 기능 | 내용 |
|---|---|
| 시즌과 기수 | "2026 감귤 시즌 남원 3기"처럼 이름 붙은 단위로 참여. 같은 거점에 모여 지낸다 |
| 현실 점검 | 예상 실수령액, 노동 강도, 숙소 조건, 출발 전 확인할 근로조건 목록 |
| 저녁·주말 밋업 | 독서회, 영화 감상회, 공유주방, 동네 돌아다니기, 한라산 등반. Agent가 참가자의 쉬는 날과 위치를 보고 장소와 시간을 제안하고, 막차나 셔틀로 돌아올 수 있는지 먼저 확인한다 |
| 한 가지 미션 | 전공이나 기술로 농가·마을에 남기는 결과물 하나 (상세페이지, 숏폼, 주문 관리 시트 등) |
| 시즌 리포트 | 일지와 미션 결과를 기록집과 경력 문서로 정리. 이주를 고민하는 사람에게는 동네 회고와 다음 연결처 |

## 5. AI Agent 설계 (기획서 필수 항목)

### 5.1 역할과 목표

| 역할 | 목표 |
|---|---|
| 수요 묶음 설계자 | 흩어진 농가 일정을 성립 가능한 시즌 단위로 묶는다 |
| 거점·노선 설계자 | 숙소 거점과 셔틀 노선을 데이터로 정한다 |
| 수지 검증자 | 모든 참여자에게 이익이 남는 조건인지 계산한다 |
| 제안서 작성자 | 상대별 근거 숫자를 골라 제안서를 쓴다 |
| 시즌 안내자 | 청년에게 준비, 생활, 기록을 안내한다 |

하나의 LLM이 도구를 골라 쓰는 단일 Agent로 구현한다.

### 5.2 사용 모델

| 용도 | 모델 |
|---|---|
| 온라인 데모 | Claude (tool use) |
| 센터 오프라인 환경 | 로컬 오픈소스 LLM 또는 키 없이 동작하는 규칙 기반 모드 |

묶기, 노선, 수지 계산은 코드로 하고 LLM은 도구 선택, 판단 설명, 제안서 작성을 맡는다.

### 5.3 Tool / API

| Tool | 입력 → 출력 | 데이터 |
|---|---|---|
| `cluster_farm_requests` | 농가 일정 목록 → 시즌 묶음과 성립 여부 | 농가 입력, 도로 거리 |
| `find_basecamp` | 묶음 위치 → 거점 마을과 숙소 후보 | 숙박업·농어촌민박 현황, 시간대별 유동인구, 업종별 매장 수 |
| `get_offseason_gap` | 읍면동·업종 → 월별 매출 변동 | 센터 카드 이용 데이터 |
| `plan_shuttle_route` | 거점·농가·인원 → 노선버스 가능 구간, 셔틀 승하차 순서와 시간 | 버스정류소·노선별 이용 |
| `check_package_economics` | 묶음·숙소·노선·단가 → 참여자별 손익 | 위 결과, 보도된 일당 수준, 입력 단가 |
| `draft_proposal` | 대상·패키지 → 제안서 | 위 결과 |
| `propose_meetup` | 참가자 위치·쉬는 날·관심사 → 모임 장소와 시간 | 버스, 유동인구, 도민 카드 소비 |
| `build_season_report` | 일지 → 기록집·경력 문서 | 내부 기록 |

### 5.4 판단 및 자율 수행 범위

| 구분 | 내용 |
|---|---|
| 스스로 수행 | 일정 묶기, 거점·노선 계산, 수지 계산, 성립하지 않는 경우의 대안 제시, 제안서 초안 작성 |
| 사람 확인 후 진행 | 제안서 발송, 패키지 공개, 단가와 분담 비율 확정 |
| 하지 않음 | 일자리 소개와 근로 계약, 숙소 예약과 결제, 차량 운행, 임금·조건 보장 |

Agent는 좋은 면만 말하지 않는다. 수지가 안 맞는 패키지는 안 맞는다고 말하고, 청년에게는 노동 강도와 숙소 편차를 그대로 보여 준다.

## 6. 데이터 활용 계획

| 기능 | 데이터 | 상태 |
|---|---|---|
| 비수기 격차 (제안서 근거) | 읍면동·업종별 월별 카드 매출 | 센터 데이터에 카드 이용 현황 있음. 숙박 업종 구분과 단위는 확인 필요 |
| 거점 찾기 | 읍면동 단위 유동인구(시간대별), 업종별 매장 수 | 공개 출품작에서 사용 확인 |
| 숙소 후보 | 숙박업·농어촌민박 현황(위치) | **미확인** |
| 셔틀 노선 | 버스정류소, 노선별 이용 | 확인. 시간표 포함 여부는 확인 필요 |
| 폐업 위험이 높은 민박 권역 | 휴폐업 | 센터 데이터로 확인 |
| 농가 일정·위치 | 사용자 입력 | 동작본에서는 가상 데이터 |
| 전세버스 업체·단가 | 없음 | 입력값으로 처리 |

이전 안보다 데이터의 역할이 분명해졌다. 센터의 카드 데이터는 "비수기에 얼마나 비는가"를 보여 주는 제안서의 핵심 근거가 되고, 버스·유동인구 데이터는 거점과 노선을 정한다.

## 8. 차별점과 기대 효과

- **Agent가 실제로 일을 한다**: 질문에 답하는 것이 아니라 흩어진 수요를 묶고, 계산하고, 제안서를 써서 거래를 성사시키는 쪽으로 움직인다.
- **비수기를 맞물린다**: 수확철 일손 부족, 겨울 민박 공실, 전세버스 유휴를 한 번에 다룬다. 새 예산 없이 이미 있는 것을 연결한다.
- **데이터가 설득의 재료다**: 카드 매출의 계절 격차가 제안서의 첫 문장이 된다.
- **정착으로 이어진다**: 몇 주 일하며 살아본 청년이 다음 시즌에 다시 오고, 그중 일부가 정착한다.

## 9. 확인이 필요한 사항과 위험

1. **수지가 실제로 맞는가**: 비수기 민박 장기 투숙 요금, 전세버스 일 단가, 농가의 추가 부담 의사를 모른다. 청년 실수령액이 남지 않으면 성립하지 않는다. 동작본은 단가를 입력값으로 두고 계산 구조를 보여 준다.
2. **세 주체를 동시에 모으는 어려움**: 민박, 버스, 농가가 모두 응해야 한다. 현실에서는 농협이나 센터 같은 운영 주체가 Agent를 쓰는 형태가 가장 가능성이 높다.
3. **직업소개 규제**: 농가 일정 접수가 구인 중개로 해석될 수 있다. 일정 확인과 알선은 농협·센터를 거치는 것으로 설계했고, 범위는 확인이 필요하다.
4. **여객운송 규제**: 통근 운행은 전세버스 사업자가 계약으로 하는 형태를 전제로 했다. 확인이 필요하다.
5. **데이터**: 숙박업 위치 데이터, 카드 데이터의 숙박 업종 구분, 버스 시간표가 제공 목록에 있는지.
6. **기존 방식**: 농협 영농작업단의 현재 수송·숙박 지원 방식. 2017~2018년에 숙식과 교통비 일부를 지원한 사례만 찾았다.
7. **안전**: 음주 모임과 겨울 산행의 책임 범위.
8. **대회 페이지 원문, 데이터 반출 규정, 오프라인 환경 사양**: 미확인.
