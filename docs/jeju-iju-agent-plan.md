## 1. 문제 정의

세 가지 문제가 따로 놀고 있다.

| 누구 | 문제 | 근거 |
|---|---|---|
| 농가 | 수확철에 사람이 없다 | "일당 10만 원에도 귤 딸 사람이 없다"(2026-11 보도). 도는 하반기 농번기에 4만 6천 명 투입 계획, 그중 1만 3천 명이 외국인 계절근로자 |
| 청년 | 제주에 살아보고 싶지만 돈이 들고, 감귤 알바는 "힘들기만 한 단기 노동"으로 끝난다 | 숙소가 열악하고 노동 강도가 높다는 후기 다수 |
| 제주 | 살아보기가 정착으로 이어지지 않는다 | 청년마을 지역살이 5,575명 중 정착 242명(약 4%). 제주 귀촌인 4년 새 20.9% 감소 |

일손 중개는 이미 제주농업인력지원센터와 농협이 한다. 비어 있는 것은 **그 몇 주를 알바가 아니라 경험으로 설계해 주는 일**이다.

## 2. 서비스 한 줄 정의

**돈 내고 하는 한달살기를, 돈 벌며 하는 제주 워킹홀리데이로 바꾼다. 일자리는 센터와 농협이 연결하고, Agent는 그 시즌을 추억과 경력으로 남도록 설계한다.**

### 대상

- 휴학생, 취업 준비생, 퇴사 후 전환기에 있는 20~30대
- 제주 이주나 귀농에 관심은 있지만 결정하기 전에 살아보고 싶은 청년

### 역할 분담

| 주체 | 하는 일 |
|---|---|
| 제주농업인력지원센터·농협 | 구인 농가 확보, 일자리 알선, 근로 조건 |
| **제주 시즌 Agent** | 시즌 계획, 동네 선택, 준비 교육, 쉬는 날 설계, 미션 제안, 기록과 회고 |

Agent는 일자리를 직접 소개하거나 계약에 관여하지 않는다. 계획이 끝나면 센터·농협 신청 안내로 넘긴다.

## 3. "알바 이상"을 만드는 다섯 가지 장치

### 추억

**① 시즌과 기수** — 날짜가 아니라 "2026 감귤 시즌 3기"처럼 이름 붙은 단위로 참여한다. Agent가 일정과 성향이 맞는 참가자를 같은 동네·같은 기간으로 묶을 수 있게 조 편성 후보를 제안한다. 혼자 내려가서 겪는 고립을 줄이고, 원안의 "청년 커뮤니티"가 여기서 생긴다.

**② 쉬는 날 지도** — 관광지 대신 그 동네 주민이 실제로 가는 곳을 데이터로 찾아 준다. 도민 카드 소비가 많은 가게, 버스로 갈 수 있는 범위, 시간대별로 사람이 모이는 곳을 묶어 쉬는 날 코스를 만든다. 차가 없는 참가자 기준으로 짠다.

**③ 시즌 일지** — 하루 한 줄을 Agent에게 남기면, 시즌이 끝날 때 일한 날, 딴 귤의 양, 다닌 곳, 만난 사람을 엮어 "나의 제주 시즌" 기록집을 만들어 준다.

### 스펙

**④ 한 가지 미션** — 일손 외에 자기 전공이나 기술로 농가·마을에 남기는 작은 결과물 하나를 정한다. Agent가 참가자의 기술과 농가의 필요를 맞춰 제안한다.

| 참가자 | 미션 예시 | 남는 것 |
|---|---|---|
| 디자인 | 농가 직거래 상세페이지·포장 디자인 | 포트폴리오 실물 |
| 마케팅·영상 | 수확기 숏폼 3편, 스마트스토어 개설 | 조회수·매출 수치 |
| 개발·데이터 | 출하 기록 정리, 주문 관리 시트 | 실사용 사례 |
| 교육·복지 | 마을 어르신 디지털 교실 1회 | 운영 기록 |

원안의 "지역사회 기여"와 "자기 직업"이 이 장치에 들어간다.

**⑤ 시즌 리포트** — 일지와 미션 결과를 근거로 경력 문서를 만든다. 근무 일수와 작업 내용, 미션 결과물, 그리고 그 경험을 이력서와 자기소개서에 쓸 수 있는 문장으로 바꾼 초안이 들어간다. 이주를 고민하는 참가자에게는 "이 동네가 나에게 맞았는가"에 대한 회고와 다음 단계(귀농귀촌종합지원센터, 제주청년플랫폼)를 덧붙인다.

리포트의 공신력은 Agent가 만들 수 없다. 센터·농협이나 농가가 근무 사실을 확인해 주는 절차는 운영 제안으로 기획서에 적는다.

## 4. AI Agent 설계 (기획서 필수 항목)

### 4.1 역할과 목표

| 역할 | 목표 |
|---|---|
| 시즌 설계자 | 참가자 조건에 맞는 시기·동네·기간을 정한다 |
| 현실 점검자 | 노동 강도, 숙소, 수입에 대한 기대를 사실에 맞춘다 |
| 동네 안내자 | 쉬는 날을 그 동네의 생활로 채운다 |
| 미션 코치 | 참가자의 기술이 농가·마을에 쓰이게 한다 |
| 기록자 | 시즌을 기록집과 경력 문서로 남긴다 |

하나의 LLM이 도구를 골라 쓰는 단일 Agent로 구현한다. 위 구분은 프롬프트 모듈과 도구 묶음이다.

### 4.2 Workflow

```
[가기 전]
1 인터뷰      기간, 체력, 전공·기술, 이동수단, 목적(경험/이주 탐색)
2 시즌 추천   작물 달력 × 동네 여건 → 시기·읍면동 후보 3개와 근거
3 현실 점검   예상 수입·생활비, 노동 강도, 숙소·근로조건 확인 목록
4 미션 정하기 기술 × 농가·마을 필요 → 미션 1개
5 신청 안내   센터·농협 연결 (여기서 일자리 알선은 기관으로 넘어감)

[가 있는 동안]
6 쉬는 날 지도  그 주의 쉬는 날 코스
7 일지          하루 한 줄 기록, 미션 진행 점검

[다녀와서]
8 시즌 리포트   기록집 + 경력 문서 + 이주 회고
```

### 4.3 사용 모델

| 용도 | 모델 |
|---|---|
| 온라인 데모 | Claude (tool use) |
| 센터 오프라인 환경 | 로컬 오픈소스 LLM 또는 키 없이 동작하는 규칙 기반 모드 |

수치 계산(수입, 점수, 집계)은 코드로 하고 LLM은 도구 선택, 대화, 글쓰기(리포트)를 맡는다.

### 4.4 Tool / API

| Tool | 입력 → 출력 | 데이터 |
|---|---|---|
| `get_crop_calendar` | 기간 → 그 시기 수확 작물과 주산지 읍면동 | 작물·재배 데이터 (확인 필요) |
| `score_base_towns` | 조건 → 지내기 좋은 읍면동 순위 | 유동인구, 버스 이용, 업종별 매장 수 |
| `estimate_season_budget` | 기간·동네 → 예상 수입과 생활비 | 보도된 일당 수준, 카드 소비 |
| `plan_day_off` | 동네·이동수단 → 쉬는 날 코스 | 도민 카드 소비, 버스, 시간대별 유동인구 |
| `suggest_mission` | 기술·동네 → 미션 후보 | 업종별 매장 수, 휴폐업, 마을 지표 |
| `log_day` / `build_season_report` | 일지 → 기록집·경력 문서 | 내부 기록 |
| `handoff_guide` | 선택 결과 → 센터·농협 신청 안내 | 기관 안내 정보 |

### 4.5 판단 및 자율 수행 범위

| 구분 | 내용 |
|---|---|
| 스스로 수행 | 데이터 조회·집계, 시기·동네 후보 압축, 예산 계산, 코스·미션 초안, 일지 기반 리포트 작성, 정보가 부족할 때 추가 질문 |
| 사용자 확인 후 진행 | 시기·동네 확정, 미션 확정, 리포트에 담을 내용 |
| 하지 않음 | 일자리 소개와 계약, 임금·근로조건 보장, 숙소 품질 보증, 법률 판단 |

Agent는 좋은 면만 말하지 않는다. 노동 강도, 숙소 편차, 보도된 성별 일당 차이를 현실 점검 단계에서 그대로 보여 주고, 출발 전 확인할 근로조건 목록(계약서, 숙소, 식사, 보험)을 준다.

## 5. 데이터 활용 계획

| 기능 | 데이터 | 상태 |
|---|---|---|
| 동네 고르기 | 읍면동 단위 내국인 유동인구, 버스 이용, 업종별 매장 수 | 공개 출품작에서 사용 확인 |
| 쉬는 날 지도 | 도민·관광객 카드 소비, 시간대별 유동인구, 버스정류소 | 공개 데이터로 확인, 단위는 확인 필요 |
| 미션 제안 | 업종별 매장 수, 휴폐업 | 센터 데이터로 확인 |
| 시즌 추천 | 작물별 재배면적·출하 시기 (읍면동) | **미확인** |

**가장 큰 위험은 시즌 추천의 데이터다.** 읍면동·월별 일손 수요 데이터는 찾지 못했다. 제공 목록에서 감귤·재배면적 데이터를 확인해, 없으면 시즌 추천은 공개된 작물 수확 시기와 주산지 정보로 단순하게 만들고 센터 데이터는 동네 고르기와 쉬는 날 지도에 집중한다. 이 경우에도 필수 조건(1종 이상)은 충족한다.

## 6. MVP 범위와 일정 (11/11 ~ 11/20)

| 우선순위 | 범위 |
|---|---|
| 필수 | 인터뷰 → 시즌·동네 추천 → 현실 점검(예산) → 쉬는 날 지도 → 시즌 리포트 생성(샘플 일지 사용) |
| 가능하면 | 미션 제안, 일지 입력 화면 |
| 기획서에만 | 기수 조 편성, 기관의 근무 확인 절차, 농가 쪽 화면 |

| 날짜 | 작업 |
|---|---|
| 11/11~12 | 데이터 목록 확인(작물, 카드, 유동인구 단위), 데이터 확보 |
| 11/13~14 | 동네 점수, 예산 계산, 쉬는 날 코스 로직 |
| 11/15~17 | Agent(도구 호출), 채팅 UI, 지도, 리포트 생성 |
| 11/18 | 미션 제안, 시나리오 테스트 |
| 11/19 | 기획서·사용자 매뉴얼 |
| 11/20 | 최종 점검, 제출 |

기술 구성: Python(pandas) + Streamlit + 지도(folium). 리포트는 HTML로 저장한다.

## 7. 차별점과 기대 효과

- **중개가 아니라 설계**: 일자리 알선은 기존 기관이 하고, Agent는 그 앞뒤(준비, 생활, 기록)를 맡는다. 기관과 경쟁하지 않고 기관의 모집을 돕는다.
- **세 문제를 한 흐름으로**: 농가 일손, 청년의 살아보기 비용, 살아보기와 정착 사이의 간극.
- **데이터가 쓰이는 자리가 분명하다**: "어느 동네에서 지낼까"와 "쉬는 날 어디 갈까"는 유동인구·버스·카드 데이터 없이는 답할 수 없다.
- **이주로 가는 낮은 문턱**: 몇 주 일하며 살아본 사람이 다음 시즌에 다시 오고, 그중 일부가 정착한다. 시즌 리포트의 이주 회고가 귀농귀촌종합지원센터 상담의 출발점이 된다.

## 8. 확인이 필요한 사항

1. **데이터 목록**: 작물·재배면적 데이터의 유무와 단위, 카드 데이터의 도민·관광객 구분과 단위.
2. **기관 연계**: 제주농업인력지원센터·농협의 현재 도외 인력 모집 조건(숙식, 항공 지원). 최근 조건은 확인하지 못했고 2017년 사례만 찾았다.
3. **직업소개 규제**: Agent가 구인 정보를 어디까지 보여 줄 수 있는지. 현재 설계는 기관 안내로 넘기는 것으로 한정했다.
4. **근무 확인 절차**: 시즌 리포트에 기관이나 농가 확인을 붙일 수 있는지는 운영 제안이며 협의된 바 없다.
5. **노동 조건의 편차**: 숙소와 임금 조건이 농가마다 다르다. Agent가 이를 미화하지 않도록 현실 점검 내용을 실제 후기와 보도로 채운다.
6. **대회 페이지 원문, 데이터 반출 규정, 오프라인 환경 사양**: 1차 안과 동일하게 미확인.
