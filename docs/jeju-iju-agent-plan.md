## 1. 문제 정의

제주로 이주하려는 청년은 정보가 없어서가 아니라 **정보가 흩어져 있고 자기 상황에 맞게 엮어 주는 주체가 없어서** 실패한다.

- 집·땅, 일자리, 지원사업, 생활 인프라 정보가 기관마다 따로 있다.
- "한 달 살기"의 제주와 "사계절 사는" 제주의 차이(겨울 바람, 차량 의존, 의료·교육 접근성, 괸당 문화)를 겪어 보기 전에는 알 수 없다.
- 혼자 내려가면 고립되고, 마을과 관계를 맺지 못한 채 2~3년 안에 떠나는 경우가 많다.
- 이주민이 소비자로만 머물면 마을에도 남는 것이 없다.

## 2. 서비스 한 줄 정의

**"어느 동네에서, 누구와, 무슨 일을 하며 살지"를 데이터로 함께 정하고, 이주 전 준비부터 정착 후 지역 기여까지 단계별로 동행하는 AI Agent.**

### 타깃 사용자

제주에 작은 집(세컨드하우스·별장)을 짓고 귀농·귀촌하며, 또래 커뮤니티를 이루어 살고 싶은 20~30대.

| 페르소나 | 상황 | 필요한 것 |
|---|---|---|
| 지은(31, 디자이너) | 원격근무 가능, 혼자 이주 고민 | 또래가 있는 동네, 작업 공간, 현실 점검 |
| 민호(34, 직장인) | 감귤 농사 + 작은 집 짓기 희망 | 농지·건축 절차, 귀농 교육, 초기 소득 계획 |
| 셋이서(29~33, 친구 팀) | 함께 내려가 카페·스테이 창업 | 상권 진단, 마을과의 관계, 공동 정착지 |

## 3. 핵심 기능 — 사용자 요구 5가지와의 대응

| 사용자 요구 | 기능 | Agent가 하는 일 |
|---|---|---|
| 이주에 필요한 모든 것을 알아봐 주고 함께함 | ① 이주 플래너 | 개인 조건을 인터뷰해 맞춤 이주 로드맵(체크리스트·일정·예산)을 만들고, 단계가 끝날 때마다 다음 할 일을 갱신 |
| 삶이 바뀌는 것을 미리 교육받음 | ② 제주살이 예습 | 선택한 동네의 실제 데이터로 "1년 시뮬레이션"을 보여 주고, 부족한 준비를 교육 과정으로 연결 |
| 청년 커뮤니티와 동네를 선택함 | ③ 동네·커뮤니티 매칭 | 읍면동을 데이터로 점수화해 추천하고, 그 동네의 청년 모임·거점과 연결 |
| 새 터전인 지역사회에 기여함 | ④ 마을 기여 매칭 | 마을에 부족한 것과 사용자가 가진 기술을 맞춰 기여 활동을 제안 |
| 자기 직업이나 사업을 함 | ⑤ 일·사업 설계 | 원격근무·취업·창업·영농 중 경로를 정하고, 입지와 수요를 데이터로 진단 |

### ① 이주 플래너
- 인터뷰: 예산, 가구 구성, 직업, 이주 시기, 원하는 삶의 형태(농사 비중, 도시 접근성 등)
- 산출물: 이주 6개월 전 → 이주 → 정착 1년의 단계별 체크리스트
- 집 짓기 트랙: 토지 조건 확인 → 농지전용·건축 인허가 절차 안내 → 농촌체류형 쉼터 같은 소규모 대안 비교
- 지원사업 트랙: 청년 귀농·귀촌 지원, 주거·창업 지원 중 자격이 되는 것만 골라 신청 시기와 서류를 정리

### ② 제주살이 예습
- **1년 시뮬레이션**: 선택한 동네의 월별 날씨, 관광객 혼잡도, 생활비, 병원·마트까지 이동시간을 달력 형태로 제시
- **현실 점검 퀴즈**: 차량 없는 생활, 겨울 난방비, 태풍 대비, 마을 행사 참여 등 이주자가 자주 놓치는 항목
- **교육 연결**: 귀농·귀촌 교육, 농업기술원 과정, 마을 살아보기 프로그램을 준비도 진단 결과에 맞춰 추천
- 결과는 "준비도 리포트"로 저장되어 플래너의 체크리스트에 반영

### ③ 동네·커뮤니티 매칭
- 읍면동 단위 **정착 적합도 점수** = 생활 인프라 + 청년 인구 비중 + 주거 비용 + 일자리·상권 + 교통 접근성 (가중치는 사용자 인터뷰로 결정)
- 추천 3곳을 지도에서 비교하고, 점수의 근거 데이터를 그대로 보여 줌
- 동네별 청년 커뮤니티·공유공간·마을회 정보를 붙여, 동네 선택과 사람 선택이 한 번에 이루어지게 함
- 팀 이주: 구성원 각자의 조건을 합쳐 공동 정착지 후보를 산출

### ④ 마을 기여 매칭
- 마을 수요 진단: 고령화율, 빈 점포, 부족 업종, 돌봄·교육 공백 등을 데이터로 파악
- 사용자의 기술(디자인, 개발, 요리, 교육, 영농 등)과 맞춰 제안 — 예: 마을 농산물 온라인 판매 지원, 어르신 디지털 교실, 빈집 활용 공유공간
- 기여 활동 기록을 쌓아 마을 정착 이력으로 활용 (지원사업 신청 시 증빙으로 쓸 수 있는 형태)

### ⑤ 일·사업 설계
- 창업: 후보 입지의 유동인구·카드매출·업종 밀집도를 분석해 과밀 업종을 피하고 빈 수요를 제시
- 영농: 지역별 재배 작물, 농지 여건, 초기 투자와 소득 시점을 정리
- 원격근무·취업: 공유오피스, 통신 여건, 지역 일자리 정보
- 원칙: 마을에 이미 있는 가게와 경쟁하는 업종보다 **마을에 없는 것**을 우선 추천 → ④와 연결

## 4. AI Agent 설계 (기획서 필수 항목)

### 4.1 역할과 목표

| Agent | 역할 | 목표 |
|---|---|---|
| 오케스트레이터 (이주 코디네이터) | 사용자와 대화하며 현재 단계를 판단하고 하위 Agent를 호출 | 사용자가 다음에 할 일을 항상 알고 있게 함 |
| 동네 분석 Agent | 읍면동 데이터를 조회·집계해 적합도 점수 산출 | 근거가 있는 추천 3곳 제시 |
| 생활 시뮬레이션 Agent | 월별 생활 조건 계산, 준비도 진단 | 이주 전 기대와 현실의 차이를 줄임 |
| 일·사업 Agent | 상권·영농·일자리 데이터 분석 | 소득 경로 1개 이상 확정 |
| 정착·기여 Agent | 지원사업 자격 판정, 마을 수요와 기술 매칭 | 지역에 뿌리내릴 활동 제안 |

MVP에서는 하나의 LLM이 도구를 골라 쓰는 단일 Agent로 구현하고, 위 구분은 도구 묶음과 프롬프트 모듈로 둔다. 마감까지 9일이므로 멀티 Agent 프레임워크 도입보다 도구 품질에 시간을 쓴다.

### 4.2 Workflow

```
[1 인터뷰] 조건·가치관 수집 → 사용자 프로필 생성
     ↓
[2 동네 추천] 데이터 조회 → 적합도 점수 → 후보 3곳 + 근거
     ↓
[3 예습] 선택 동네의 1년 시뮬레이션 → 준비도 리포트
     ↓
[4 일·사업] 소득 경로 선택 → 입지·수요 진단
     ↓
[5 로드맵] 체크리스트·일정·예산·지원사업 통합 문서 생성
     ↓
[6 정착 후] 마을 기여 제안, 체크리스트 갱신 (반복)
```

각 단계에서 Agent는 "정보가 충분한가"를 스스로 판단해 부족하면 질문하고, 충분하면 다음 단계로 넘어간다. 사용자는 어느 단계로든 돌아갈 수 있다.

### 4.3 사용 모델

| 용도 | 모델 | 이유 |
|---|---|---|
| 온라인 데모 | Claude (Sonnet급) + tool use | 도구 호출 정확도, 한국어 품질 |
| 오프라인 분석환경 탑재 | 로컬 오픈소스 LLM (Ollama 등) | 센터 환경이 외부망과 분리되어 있을 가능성에 대비 |

모델 호출부를 인터페이스로 분리해 둘을 교체할 수 있게 한다. 점수 계산과 통계는 LLM이 아니라 코드(pandas)로 수행하고, LLM은 도구 선택과 해설만 맡는다. 수치를 LLM이 지어내지 못하게 하기 위함이다.

### 4.4 Tool / API

| Tool | 입력 → 출력 | 데이터 |
|---|---|---|
| `get_district_profile` | 읍면동 → 인구·연령·인프라 요약 | 제주데이터허브 |
| `score_districts` | 가중치 → 읍면동 적합도 순위 | 제주데이터허브 + 빅데이터센터 |
| `simulate_year` | 읍면동 → 월별 날씨·혼잡·생활비 | 기상·관광·소비 데이터 |
| `analyze_commerce` | 위치·업종 → 매출·밀집도·유동인구 | 빅데이터센터 카드·유동인구 |
| `find_support_programs` | 프로필 → 자격 되는 지원사업 | 지원사업 공고 (정리된 표) |
| `match_contribution` | 읍면동·기술 → 기여 활동 후보 | 마을 수요 지표 |
| `build_roadmap` | 프로필·선택 결과 → 체크리스트 문서 | 내부 생성 |

### 4.5 판단 및 자율 수행 범위

| 구분 | 내용 |
|---|---|
| 스스로 수행 | 데이터 조회·집계, 점수 계산, 후보 압축, 로드맵 초안 작성, 부족한 정보 추가 질문 |
| 사용자 확인 후 진행 | 동네 최종 선택, 소득 경로 확정, 가중치 변경 |
| 하지 않음 | 계약·신청 대행, 법률·세무·인허가의 확정적 판단, 투자 수익 보장 |

인허가·세금·지원사업 자격은 "확인이 필요한 항목"으로 표시하고 담당 기관을 안내한다. 모든 추천에는 근거 데이터와 기준 시점을 함께 표시한다.

## 5. 데이터 활용 계획

필수 조건(1종 이상)을 넘어, 핵심 기능마다 데이터가 실제 판단 근거로 쓰이게 한다. 동점 시 심사 항목인 "필수 데이터 활용 적절성"에 대응한다.

| 기능 | 필요한 데이터 유형 | 출처 후보 |
|---|---|---|
| 동네 적합도 | 읍면동별 인구·연령, 전입·전출, 의료·교육·교통 시설 | 제주데이터허브 |
| 1년 시뮬레이션 | 월별 관광객·유동인구, 기상, 소비 | 빅데이터센터, 데이터허브 |
| 상권 진단 | 업종별 카드매출, 유동인구, 사업체 현황 | 빅데이터센터 |
| 영농 설계 | 작물 재배 현황, 농지 정보 | 데이터허브 |
| 마을 수요 | 고령화율, 빈집, 업종 공백 | 데이터허브 |

**먼저 할 일**: 제공된 1,259종 목록에서 위 유형에 해당하는 데이터셋을 실제 이름으로 확정한다. 위 표는 유형 수준의 가정이며, 목록에 없는 항목은 기능 범위를 조정한다.

## 6. MVP 범위와 일정 (11/11 ~ 11/20)

마감까지 9일이므로 5개 기능 전부를 얕게 만드는 것보다 **③ 동네 매칭과 ② 예습을 실제 데이터로 깊게** 만들고, 나머지는 로드맵 문서 안에서 연결한다.

| 우선순위 | 범위 |
|---|---|
| 필수 | 인터뷰 → 동네 추천(점수 + 근거 + 지도) → 1년 시뮬레이션 → 로드맵 문서 |
| 가능하면 | 상권 진단(창업 트랙 1개), 지원사업 매칭 |
| 기획서에만 | 커뮤니티 실시간 연결, 기여 이력 관리, 정착 후 동행 |

| 날짜 | 작업 |
|---|---|
| 11/11~12 | 데이터 목록 검토, 데이터셋 확정·확보, 반출 규정 확인 |
| 11/13~14 | 데이터 전처리, 적합도 점수·시뮬레이션 로직 |
| 11/15~17 | Agent(도구 호출) + 채팅 UI + 지도 |
| 11/18 | 상권 진단·지원사업 매칭, 시나리오 테스트 |
| 11/19 | 기획서·사용자 매뉴얼 작성, 데모 정리 |
| 11/20 | 최종 점검 후 제출 |

기술 구성: Python(pandas) 분석 + Streamlit 채팅 UI + 지도(folium). 설치와 실행이 단순해 오프라인 환경 탑재와 매뉴얼 작성에 유리하다.

## 7. 차별점과 기대 효과

- **관광이 아닌 정착**: 제주 데이터 활용 서비스 대부분이 관광·상권에 집중되어 있다. 인구 유출과 청년 정착은 도의 정책 과제와 직접 맞닿는다.
- **추천에서 끝나지 않는 동행**: 한 번 답하고 끝나는 챗봇이 아니라 단계와 체크리스트를 유지하는 Agent다.
- **이주민과 마을 양쪽의 이익**: 마을에 없는 것을 우선 추천하고 기여 활동을 설계해 원주민과의 갈등을 줄인다.
- **센터 상시 탑재에 적합**: 이주 상담 창구나 귀농귀촌지원센터에서 상담 도구로 쓸 수 있다.

## 8. 확인이 필요한 사항

1. **대회 페이지 원문**: 작업 환경에서 daker.ai 접속이 막혀 있어 0장은 언론 보도와 검색 요약에 근거했다. 제출 양식, 분량 제한, 세부 유의사항은 원문 대조가 필요하다.
2. **데이터 목록**: 1,259종 중 5장의 유형에 맞는 데이터셋이 실제로 있는지, 읍면동 단위로 제공되는지.
3. **데이터 반출 규정**: 빅데이터센터 데이터가 센터 내 분석 전용이라면 집계 결과만 반출하는 구조로 바꿔야 한다.
4. **오프라인 환경 사양**: 외부 LLM API 사용 가능 여부. 불가능하면 로컬 모델이 기본이 된다.
5. **제도 정보**: 농지전용, 농촌체류형 쉼터, 청년 귀농 지원사업의 현행 조건은 구현 시 공식 공고로 확인해 반영한다.
